# Часть I. Работа с локальным репозиторием

Для выполнения работы была создана простая программа на Go, определяющая операционную систему с помощью `runtime.GOOS`.

Исходная версия программы поддерживала Windows и Linux:

```go
switch runtime.GOOS {
case "windows":
    fmt.Println("Program supports Windows")
case "linux":
    fmt.Println("Program supports Linux")
default:
    fmt.Println("Unsupported operating system")
}
```

## 1. Создание локального репозитория

В каталоге проекта был создан локальный Git-репозиторий:

```bash
git init
```

После этого исходный файл был добавлен в индекс:

```bash
git add .
```

Создан первый коммит:

```bash
git commit -m "init"
```

Первый коммит сохранил исходное состояние программы.

## 2. Создание ветки без поддержки Windows

Создана отдельная ветка:

```bash
git switch -c no-window
```

Из программы была удалена поддержка Windows.

Изменения были зафиксированы:

```bash
git add .
git commit -m "remote window"
```

В результате ветка `no-window` содержит версию программы без поддержки Windows.

## 3. Создание ветки без поддержки Linux

После возвращения к исходной ветке:

```bash
git switch main
```

была создана вторая ветка:

```bash
git switch -c no-linux
```

В этой ветке была удалена поддержка Linux.

Изменения были зафиксированы:

```bash
git add .
git commit -m "remote linux"
```

В результате были получены две ветки с различными изменениями исходной программы.

## 4. Слияние ветвей и разрешение конфликта

Для объединения изменений было выполнено переключение на ветку `no-window`:

```bash
git switch no-window
```

После этого выполнено слияние:

```bash
git merge no-linux
```

Git обнаружил конфликт, поскольку обе ветки изменяли один и тот же участок файла `main.go`.

Конфликт был разрешён вручную. В итоговой версии была восстановлена поддержка Windows и Linux.

После разрешения конфликта файл был добавлен в индекс:

```bash
git add .
```

Слияние было зафиксировано:

```bash
git commit -m "Merge branch 'no-linux' into no-window"
```

## 5. Просмотр истории изменений

История изменений была просмотрена командой:

```bash
git log --oneline --graph --all
```

История содержит исходный коммит, две ветки, изменения в каждой ветке и последующее слияние.

Итоговая последовательность коммитов:

```text
init
remote window
remote linux
Merge branch 'no-linux' into no-window
Restore initial version
```

## 6. Основные использованные команды Git

| Команда | Назначение |
|---|---|
| `git init` | создание локального репозитория |
| `git status` | просмотр состояния репозитория |
| `git add` | добавление изменений в индекс |
| `git commit` | фиксация изменений |
| `git switch` | переключение между ветками |
| `git switch -c` | создание и переключение на новую ветку |
| `git merge` | слияние ветвей |
| `git log` | просмотр истории |
| `git diff` | просмотр различий |
| `git restore` | восстановление файла |

## 7. Восстановление исходной версии

Для восстановления исходного состояния программы был использован первый коммит:

```bash
git restore --source=eae3816 -- main.go
```

После восстановления файл был добавлен в индекс:

```bash
git add main.go
```

и создан отдельный коммит:

```bash
git commit -m "Restore initial version"
```

Таким образом, исходная версия программы была восстановлена из истории Git.

# Часть II. Работа с глобальным репозиторием

## 1. Сравнение CVS, SVN и Git

CVS, SVN и Git предназначены для управления версиями исходного кода, но используют разные подходы к организации репозитория.

**CVS** — централизованная система контроля версий. Основная информация хранится на центральном сервере.

**SVN** — также централизованная система. Рабочие копии разработчиков синхронизируются с центральным репозиторием.

**Git** — распределённая система контроля версий. Локальный репозиторий содержит историю проекта и позволяет выполнять большинство операций без постоянного подключения к серверу.

| Характеристика | CVS | SVN | Git |
|---|---|---|---|
| Тип системы | централизованная | централизованная | распределённая |
| Локальная история | ограниченная | рабочая копия | полная история |
| Работа без сервера | ограниченная | ограниченная | большинство операций |
| Ветвление | поддерживается | поддерживается | активно используется |
| Локальные коммиты | ограниченно | нетипичный сценарий | стандартный сценарий |

## 2. Глобальные репозитории

Для хранения удалённых Git-репозиториев используются сервисы:

- GitHub;
- GitLab;
- Bitbucket.

Они позволяют хранить проекты удалённо, синхронизировать изменения и организовывать совместную работу.

## 3. Работа с GitHub

В качестве глобального репозитория был рассмотрен GitHub.

Основная последовательность работы:

1. Создание учётной записи.
2. Создание удалённого репозитория.
3. Связывание локального репозитория с удалённым.
4. Передача локальных коммитов на сервер.
5. Получение изменений с сервера.

Для добавления удалённого репозитория используется:

```bash
git remote add origin <repository-url>
```

Для передачи локальной ветки:

```bash
git push -u origin main
```

Для получения информации об изменениях:

```bash
git fetch
```

Для получения и объединения изменений:

```bash
git pull
```
